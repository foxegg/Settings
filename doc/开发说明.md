# 开发说明

一期是手机上的辅助批改：CameraX 预览，OpenCV 跟踪纸面，点「批改」才请求一次多模态模型，把对钩、叉和短批注叠在画面上。产品约定见 [技术方案.md](技术方案.md)。

## 用 Android Studio 打开

1. 安装 Android Studio（带 Android SDK 36）和 JDK 17 或更高版本。
2. 选 **File → Open**，打开本仓库根目录（含 `settings.gradle.kts` 的那一层），不要只打开 `app/`。
3. 等 Gradle 同步完成。若提示写入 `local.properties` 里的 `sdk.dir`，让 Studio 写上本机 SDK 路径。
4. 运行 `app` 配置，装到一台有后置相机的手机上。模拟器没有真实纸面，只能看界面，不能验证对准。

命令行编译调试包：

```bash
./gradlew assembleDebug
```

单元测试（不需要手机）：

```bash
./gradlew testDebugUnitTest
```

## 接口密钥

密钥、地址和模型名都在仓库根目录的 `local.properties` 里。这个文件已在 `.gitignore` 中，不要提交。Android Studio 还会在同一个文件里写 `sdk.dir`，两套配置放在一起即可。示例见 `local.properties.example`。

```properties
GRADING_API_BASE=https://dashscope.aliyuncs.com/compatible-mode/v1
GRADING_API_MODEL=qwen3-vl-plus
GRADING_API_KEY=
```

默认是阿里云百炼（Model Studio）北京地域的 OpenAI 兼容接口，模型 `qwen3-vl-plus`。官方说明 `https://dashscope.aliyuncs.com` 仍然可用，应用会自己在末尾加上 `/chat/completions`，配置里不要再加这一段。图像按官方兼容格式发送：`data:image/jpeg;base64,...`。

密钥和地域必须一致：

- 北京密钥用默认地址。
- 国际站（新加坡）密钥把地址改成 `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`。
- 控制台如果给了业务空间专属域名，把 `{WorkspaceId}` 换成空间 ID，例如 `https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`。

留空 `GRADING_API_BASE` 或 `GRADING_API_MODEL` 时，应用仍使用上面的百炼默认值。`qwen3-vl-plus` 在百炼文档里默认不开启思考模式，这一期也不额外打开它，避免把思考过程当成批注。

可选：手机能访问 Google API 时，可以改成 Gemini 3.1 Pro，而不是默认的百炼。OpenAI 兼容地址和模型名是：

```properties
GRADING_API_BASE=https://generativelanguage.googleapis.com/v1beta/openai
GRADING_API_MODEL=gemini-3.1-pro-preview
GRADING_API_KEY=
```

访问不到 Google 时不要用这组配置。应用只实现了一种 OpenAI chat completions 请求，换接口只改这三行。

改完 `local.properties` 后重新同步 Gradle 再运行。密钥会进 Debug 包的 `BuildConfig`，不要把打出来的 APK 发给别人。

## 演示模式

没有密钥时，开关「演示模式」默认打开。点「批改」不会联网，只把技术方案里的示例标记叠到当前跟踪到的纸面上：

```json
{"marks":[{"type":"check","x":0.72,"y":0.18},{"type":"cross","x":0.72,"y":0.31},{"type":"text","x":0.80,"y":0.45,"text":"要点不完整"}]}
```

纸还没被跟踪到时不会叠标记。叠上之后移动、转动或轻斜试卷，标记只跟着网格走，不会再次请求模型。再点一次「批改」才会换一批结果；演示模式仍然不联网。

关掉演示模式且填了密钥时，还要在输入框里写评分标准或参考答案。应用把纠正后的试卷图和这段文字原样交给模型，自己不对答案、不算分，也不要求老师先审核再显示。

## 一期做了什么

- 相机权限说明，拒绝后可以再请求或去系统设置。
- CameraX 预览和取帧。分析分辨率目标 1920×1080，预览用 `FILL_CENTER`，和取帧共用一个 ViewPort，让叠层和画面是同一块裁切。
- 纸面四边检测，加上 Lucas-Kanade 光流和 RANSAC 单应性。手挡住一部分时，用剩下的特征点继续更新；整页都挡住时会短暂保持上一帧，随后重新寻找。
- 4×4 格子的网格。轻微翘角或褶皱体现在格子的局部位移上，标记用格子内的双线性插值贴到纸面坐标。
- 网格相对单应性的偏差过大时，顶部提示先把试卷摊平。深折痕和卷曲对不齐，这是预期限制。
- 纸面稳定一小段时间后锁定 AE/AWB，并把 AF 模式设为关闭。也可以手动「锁定对焦 / 解除锁定」。不同手机对锁焦的支持不完全一样。
- 「批改」按钮：有纸面时把当前帧纠正成正视 JPEG，连同评分标准请求一次模型，解析 `marks` 后开始叠加。之后只更新叠层位置。
- 标记类型：`check`、`cross`、`underline`、`circle`、`text`。坐标是纸面归一化坐标，原点在左上，宽和高都是 1。叠层只画这些笔画，不把试卷照片或模型生成的整页图盖上去。

## 一期不做

- 投影仪输出、相机和投影仪的标定、电脑端程序。
- 在应用里比较答案或计算分数。
- 每一帧或跟踪过程中调用模型。
- 保存历史批改结果。换卷后再点一次「批改」。

## 跟踪限制

白桌、光照很平、纸边和桌面几乎没有对比时，可能一开始找不到纸。请让纸和桌面有一点明暗差，并先让整张纸进入画面，跟踪锁上之后再把手放上去写。分析用大约 640 像素宽的灰度图做跟踪，纠正后送给模型的长边是 1600 像素。这是一期可运行的实现，不是实验室标定过的测量系统。

## 依赖版本

版本以仓库里的 Gradle 文件为准，选取时核对过公开仓库，没有用尚不存在的版本号：

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| Android Gradle Plugin | 8.13.2 | 稳定版。更新的 9.x 改了构建写法，这一期不跟。 |
| Gradle | 8.13 | AGP 8.13 要求的最低版本。 |
| Kotlin | 2.2.21 | 与上面的 Gradle / AGP 搭配的稳定版。 |
| compileSdk / targetSdk | 36 | 已安装的 Android 36 平台。minSdk 26。 |
| CameraX | 1.6.2 | 截至 2026-11-04 发布页上的稳定版，不是 1.7 的候选版。 |
| OpenCV Android | 4.14.0 | Maven Central 上的 Android AAR（2026-07）。用的是 `OpenCVLoader.initLocal`、`Imgproc`、`Video`、`Calib3d`。5.1.0 已发布，但是新的主版本，这一期不采用。 |
| Material | 1.14.0 | |
| AppCompat | 1.8.0 | |
| Core KTX | 1.18.0 | 1.19 要求 Android Gradle Plugin 9.1 和 compileSdk 37，这一期没有跟。 |

OpenCV 的原生库如果还不是 16 KB 页对齐，上架 Google Play 前需要换成对齐过的构建。一期只要求 `assembleDebug` 能编过。
